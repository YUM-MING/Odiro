# 코스 평가 스크립트 (`scripts/eval_courses.py`)

> 2주차(11/18)에 만들고 기준선을 한 번 돌렸다. 코스 품질을 바꾸는 작업은 **바꾸기 전에 한 번, 바꾼 뒤에 한 번** 돌려 이 표로 전후를 비교한다.
> 인수인계 문서: [HANDOVER.md](HANDOVER.md). 테스트: `tests/test_eval_courses.py` (네트워크 없이 지표 계산만 검증).

## 1. 무엇을 하는가

시나리오 10개를 **실제로** 돌린다 (캐시 없이 `run_course(use_cache=False)`). LLM·카카오 지도·날씨 API 를 진짜로 호출하므로 **시나리오 1개당 20~60초, OpenAI 비용이 든다** (코스 1건 10~20원, 10개면 약 100~200원). 한 시나리오가 죽어도 나머지는 계속 돈다.

## 2. 실행

```bash
python scripts/eval_courses.py                                   # 전체 10개, 결과 저장
python scripts/eval_courses.py --only seongsu_walk gapyeong_trip # 일부만
python scripts/eval_courses.py --date 2026-11-25                 # 출발일 지정 (기본: 오늘+2일)
python scripts/eval_courses.py --compare cache/eval/20261118-1952.json   # 이전 결과와 전후 비교표 덧붙이기
python scripts/eval_courses.py --no-save                         # 저장 안 함
```

- 결과는 `cache/eval/<시각>.json` (원자료)과 `.md` (표)로 저장된다. **`cache/` 는 git 에 안 올라가므로** 의미 있는 결과는 이 문서 6번에 표를 옮겨 적는다.
- 출발일은 **예보가 잡히는 5일 안쪽**이어야 날씨가 나온다. 날씨는 날짜에 따라 정해지므로 같은 시나리오도 날짜가 다르면 결과가 달라진다. 전후 비교는 **같은 `--date`** 로 한다.
- 종료 코드: 확인 안 된 장소가 하나라도 있으면 `1`, 아니면 `0`.
- 서버(uvicorn)는 필요 없다 (에이전트를 직접 호출). `.env` 의 키가 있어야 한다.

| 열 | 의미 | 좋은 값 |

| 날씨 | 예보 요약 (참고용) | - |
| 경고 | 응답 `meta.warnings` 개수 | 적을수록 |
| 시간(초) | 코스 생성 시간 | 목표 40초 이하 |

**해석 (검증하지 않음)**
- 코스는 LLM 초안이 매번 달라서 같은 조건도 결과가 흔들린다 (성수동 53.7초는 다른 도보 시나리오의 2배). **1회 결과로 개선 여부를 단정하지 말고, 같은 조건을 2~3번 돌려 본다.**
